## BUG-094 — Gaussian splat reconstruction does not resemble the room

**Date filed:** 2026-08-07  
**Area:** host/splat  
**Status:** fixed + verified 2026-08-07

Sam Office rebuilt with the fix: **final loss 0.357 → 0.026** (14×), and rendered
interior views now clearly show the office — desk + monitors along one side, the
wood-framed window with blinds, a floor lamp, and object-filled shelves across —
instead of the colorful floater cloud. Residual edge floaters remain where view
coverage is thin (161/287 registered), which is expected 3DGS behaviour.

### Root cause (isolated by A/B on a held-out COLMAP model)

Not COLMAP, not the coordinate frame, not the renderer: a **rendered training
view was grossly aligned with the ground-truth photo** (bright window on the
right, dark ceiling on top), so the camera poses were correct. The gaussians
simply never sharpened — they stayed as huge blurry anisotropic *needles*, PSNR
stuck at ~8–9 dB (a converged 3DGS reaches 25–35), and the training loss
oscillated 0.2–0.7 without ever dropping. That is the "galaxy of colors".

Two defects in `roomscan/splat/train.py`, both in the loss path:

1. **The hand-rolled `_ssim`** used box-filter variances `E[x²]−E[x]²` that dip
   slightly negative from float rounding, so the SSIM ratio and its gradient blew
   up and actively **drove the loss upward**. A/B on the same model: pure L1
   reached **25.0 dB**; L1 + the broken SSIM **diverged to 8.8 dB** with the loss
   climbing to 0.72.
2. **`pred = render[0].clamp(0, 1)`** before the loss zeroed the gradient on every
   saturated pixel — and a bright ceiling/window fills much of an indoor frame.

### Fix

- Replaced `_ssim` with a standard **11×11 Gaussian-window SSIM with variances
  clamped ≥ 0** (per-channel `conv2d`, `groups=3`).
- **Removed the `.clamp(0, 1)`** from the loss path (raw render, as gsplat does).
- Added the MCMC **opacity + scale regularisers** (0.01 each) so gaussians can't
  grow into needles, and adopted gsplat's canonical step order (optimiser step
  before `step_post_backward`, no `step_pre_backward`).

Re-verified on the held-out model: **7 → 23.9 dB**, scales shrink, and the
rendered view clearly shows the room (ceiling, wood-framed window + blinds, wall
scroll, speaker). Sam Office rebuilding with the fix.

### Original report

The 3D Gaussian splat offline reconstruction produces a result that bears little resemblance
to the actual room being scanned. The reconstruction appears to be distorted, misaligned,
or otherwise corrupted compared to the reference room geometry visible in the point cloud
and SLAM mesh outputs.

**Evidence:** See [bug-094.png](@lidar-roomscanner/bugs/bug-094/bug-094.png) for a visual
comparison between the expected room structure and the observed splat output.

**Scope:**  
- Likely affects the `roomscan.splat` pipeline or the integration between SLAM output and
  the Gaussian splat builder
- May involve coordinate frame misalignment, incorrect camera pose application, or
  depth/intensity encoding issues in the splat data
- Need to isolate whether the issue is in the builder, the renderer, or the data
  being passed to the builder

**Next steps:**  
1. Verify the builder receives correct mesh/pose data via an intermediate dump
2. Check frame alignment and coordinate convention in the splat pipeline
3. Compare against known-good synthetic data to narrow the failure mode
