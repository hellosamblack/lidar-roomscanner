# BUG-085: Web UI frozen with missing comm-status due to JS initialization errors in static modules

**Status:** fixed  
**Area:** host/web  
**Date:** 2026-08-07  
**Files:**
- `host/src/roomscan/static/layout.js`
- `host/src/roomscan/static/scene.js`
- `host/src/roomscan/static/browser.js`

## Description

The web application UI (`roomscan-web`) became frozen and unresponsive, with the top-bar comm-status indicator completely missing, even while the server and scanner hardware were reachable and actively streaming UDP ToF/IMU frames.

## Root Cause

Client-side JavaScript exceptions during ES module initialization halted `app.js` before `hub.connect()` could open the `/ws` WebSocket connection:

1. **`layout.js` SyntaxError**: An early `return; }` inside `updateSquircles()` left dangling code outside any function block and an extra closing brace on line 224 (`Unexpected token 'var'`).
2. **`scene.js` ReferenceError**: `createScene()` included `setViewportMirror` in its export dictionary, but the function declaration itself was omitted, throwing `Uncaught ReferenceError: setViewportMirror is not defined` when `app.js` called `createScene(hub)`.
3. **`browser.js` ReferenceError**: `createBrowser` omitted `scene` in its parameter signature while referencing `scene` on line 198, and used an undeclared `selectedDetail` variable.

Because `app.js` crashed on startup, no WebSocket connection was established, leaving top-bar link indicators unpopulated and UI interactive listeners unattached.

## Fix

1. Fixed function block enclosing in `layout.js`.
2. Implemented `setViewportMirror(on)` (`renderer.domElement.style.transform = on ? 'scaleX(-1)' : ''`) in `scene.js`.
3. Added `scene` parameter and replaced `selectedDetail` with `previewCard` in `browser.js`.
4. Verified end-to-end with headless Chrome (`web_ui_shot.py`), confirming clean WebSocket connection (`ws.js: OPEN`) and frame reception with 0 console errors.
