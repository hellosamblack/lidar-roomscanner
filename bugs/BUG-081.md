## BUG-081 — Manual ranging number fields revert mid-type — the ~4 Hz `ranging` echo re-seeds a focused field

- **Status:** **fixed** 2026-08-05 · **Reported:** 2026-08-05 (owner, found in the use-case-preset UI pass) · **Area:** host/web UI
- **Where:** `host/src/roomscan/static/controls.js` (`manualEditing` focus guard on the Manual fps/exposure inputs)

Distinct from **BUG-079**, which fixed the *debounce-vs-broadcast* race with a `manualDirty` flag
cleared on a `pending` true→false transition. `manualDirty` is set only when an edit is **committed**
(on `change`, i.e. blur/Enter), so it does not cover a value that is still being *typed*: while the
user was entering "25", the ~4 Hz `ranging` echo re-seeded the field to the currently applied value
right after the "2" — clearing the entry and forcing a re-click.

**Fix:** track focus separately (`manualEditing`) and suppress the periodic `ranging` re-seed for as
long as a Manual number field holds focus, in addition to the existing `manualDirty` suppression. The
field keeps whatever the user is typing until they commit or blur.
