# BUG-086: socket.send() raised exception terminal warning flood on client disconnect

**Status:** fixed  
**Area:** host/web  
**Date:** 2026-08-07  
**Files:**
- `host/src/roomscan/web.py`

## Description

Server terminal flooded with `socket.send() raised exception.` warnings from Python 3.12 `asyncio` (`selector_events.py` line 1068 / `proactor_events.py` line 353) whenever a WebSocket client disconnected or refreshed.

## Root Cause

`roomscan-web` runs high-frequency (up to ~90 Hz) broadcast loops for point cloud, IR, sensor, and MESH data. When a client disconnected or closed a tab:

1. High-frequency broadcast iterations (`_broadcast_bytes`, `_broadcast_text`, `_pump_mesh`) continued attempting to write frames to dead sockets until the drop handler completed.
2. In `_drop_client` and `_drop_mesh_client`, `ws.close()` was unconditionally called even when the transport connection was already disconnected. Calling `ws.close()` on a disconnected `WebSocket` sent an ASGI `websocket.close` message down to `starlette`, which attempted to write to `asyncio`'s lost transport.
3. Python 3.12's `asyncio` logs `logger.warning('socket.send() raised exception.')` for writes made to a connection whose transport is marked as lost (`_conn_lost >= LOG_THRESHOLD_FOR_CONNLOST_WRITES`). At ~90 Hz frame cadence, a single disconnected client triggered dozens of warnings per second in the server terminal stdout/stderr.

## Fix

1. Added `_ws_is_connected(ws)` helper checking that both `ws.client_state` and `ws.application_state` equal `WebSocketState.CONNECTED`.
2. Updated `_broadcast_bytes`, `_broadcast_text`, and `_pump_mesh` to verify `_ws_is_connected(ws)` before attempting binary/text frame sends, cleanly dropping disconnected clients without writing to dead transports.
3. Updated `_drop_client` and `_drop_mesh_client` to gate `await ws.close()` behind `_ws_is_connected(ws)`, eliminating redundant close writes on lost connections.
